# Audit 2026-11-26: vision model, speed, security

Read-only audit. No app or Worker code changed. Every number below was measured on 2026-11-26 unless marked "not verified".

## Verdict

The game works today (live recognition returned correct answers in every probe). Three things need action before **December 1, 2026**:

1. **The vision model is being retired.** Google reroutes `gemini-2.5-flash` to `gemini-3.5-flash-lite` on Dec 1. Nobody has tested our 109 items on the new model.
2. **Monitoring has been off since August 16.** GitHub disabled the 6-hour health probe for repo inactivity (`disabled_inactivity`). If the Dec 1 switch breaks recognition, nothing will tell us.
3. **The Worker is an open door to the paid Gemini key.** Anyone can send it any prompt. Confirmed: a text-only "say pong" request returned "pong".

## 1. Vision model

| Fact | Source |
|---|---|
| `gemini-2.5-flash` deprecated; from Dec 1, 2026 all calls route to `gemini-3.5-flash-lite` | ai.google.dev deprecations + Nov 2 changelog |
| Price is unchanged: $0.30 in / $2.50 out per 1M tokens | ai.google.dev pricing |
| Gemini 3 models ignore `temperature` (and will reject it in later generations) | 3.6 migration guide |
| Default thinking on 3.5 Flash-Lite is "minimal" | same |
| Paid tier still excluded from training on every model | pricing page |

- **Is the current model sufficient?** Yes on accuracy (June eval: 109/109 recognized). The question is moot after Dec 1 because it stops existing.
- **Recommendation: stay on Google, pin `gemini-3.5-flash-lite` on purpose, gated by the eval.** A yes/no "is there a shoe in this photo" check is the easiest job in vision. A bigger model buys nothing a toddler would notice. Cost is about $0.0005 a photo either way, so price is not the deciding factor.
- **Fallback if the eval regresses:** `gemini-3.6-flash` ($0.75 / $3.75 now, doubling Jan 1, 2027). Still fractions of a cent per photo.
- **Strongest argument against:** a "lite" model could be looser or stricter on messy toddler photos than 2.5 Flash was. The ph-tools eval (109 items + the 218-test false-positive pass) answers that in about an hour. Run it on both candidates before choosing.
- **Not worth doing:** switching vendor. The privacy policy names Google, billing is set up, and the paid-tier no-training term is what makes the privacy claim true.
- **Rule to retire:** CLAUDE.md's "temperature 0" hard rule no longer does anything on Gemini 3. Consistency now comes from the prompt and minimal thinking.

## 2. Recognition speed

Measured from this laptop through the live Worker, realistic 1024x768 photo, 4 runs each:

| Setup | Round trip |
|---|---|
| Current (thinking on, yes/no + description line) | 1.45 to 1.83 s |
| Thinking off, yes/no only | 1.16 to 1.32 s |

- Every call pays for 82 to 132 "thinking" tokens plus about 33 tokens describing the photo. The app reads only the first line and throws the description away. Dropping both is roughly 25% faster and removes almost all output cost.
- No retry. One slow or failed call shows the "Camera Nap" card. One automatic retry (second attempt on a fallback model) inside the Worker would hide most blips from the child.
- Not verified: latency on a phone over cellular. Upload of a real photo (150 to 300 KB) adds to these numbers.

## 3. App load speed

- Site response is fast: 130 to 220 ms to first byte for the landing page, game page, script and stylesheet.
- **First visit downloads about 22 MB in the background** (111 images = 14.5 MB, 106 audio clips = 7.7 MB) because the service worker pre-caches everything at once.
- **The art is PNG.** Converting the pre-cached art to WebP takes it from 13.9 MB to 2.0 MB (measured, same pixel size). Biggest single speed win.
- `fox-hero.png` (349 KB) is the first image on both the landing page and the game.
- **Fonts load from Google** on every page. That blocks first paint on a third party, is not cached for offline, and sends each visitor's IP to Google, which the privacy policy does not mention. Self-host the one font file.
- About 7 MB of old duplicate PNGs sit in `play/img/` root (blanket, brush, towel, pillow, lamp, remote, square at about 1 MB each). Only `square.png` (740 KB) is actually served. Plus 4 dead cut-mode scripts in `play/content/`.

## 4. Security

| # | Finding | Evidence | Severity |
|---|---|---|---|
| 1 | Worker forwards any request body to Gemini with the paid key | text-only prompt returned "pong" | High |
| 2 | Origin check is a prefix match | `https://picturehunt.app.example.com` was accepted | Medium |
| 3 | The shared token is not enforced (Worker secret never set) | request with no token went through | Low (token is public anyway) |
| 4 | Rate limit spends one KV write per photo and fails open on error | `worker.js` rateLimitOk | Medium |
| 5 | No rate limit at all on code validation or progress sync | `worker.js` | Low |
| 6 | Site still answers on plain http (no redirect) | http returned 200; GitHub shows `https_enforced: false`, cert approved | Medium, one toggle |
| 7 | Health probe disabled since 2026-08-16 | `gh workflow list` | High |
| 8 | Probe passes on any text answer, so it would not catch a model that answers wrongly | workflow file | Medium |
| 9 | If photo shrinking fails, the original (with GPS data) is sent | `app.js` downscalePhoto fallback | Low, rare |
| 10 | Dead "paste your own Gemini key" path still ships and is allowed by the page security policy | `app.js` top, CSP | Low |
| 11 | Promo codes are public and premium is a browser flag | known, accepted until payments | Must fix before charging |
| 12 | Purchased codes expire after 365 days despite "yours forever" | `worker.js` webhook, known and deferred | Must fix before charging |

On finding 4: Cloudflare's free plan allows 1,000 KV writes a day (plan not verified). Past that, the limiter silently stops limiting, and the same quota is what purchase codes and progress sync write to.

**The right fix for 1 to 5 is one change:** the Worker builds the Gemini request itself. The app sends only category, item name and photo. The Worker holds the prompts, the model name and the fallback, checks the item against the real list, and uses Cloudflare's built-in rate limiter instead of KV. That closes the open door, and future model changes need no app update or cache bump.

## 5. Recommended order

Before Dec 1:
1. Re-enable the health probe. Make it send a real photo and require "Yes". Move it to a Cloudflare scheduled job so inactivity cannot switch it off again.

3. Ship the Worker rewrite (server-side prompts, pinned model, fallback + one retry, exact origin match, built-in rate limiter, yes/no only, minimal thinking).
4. Turn on "Enforce HTTPS" in GitHub Pages.

After:

6. Delete dead files, remove the dead key path, block the GPS fallback.
7. Set a monthly budget alert on the Google billing account.
